## Key Interactions to Verify

1. Войти и настроить тестовый план; до первого импорта отсутствующие данные не показаны как нулевые. После импорта видны время и покрытие каждого нужного источника.
2. Для синтетической недели 50 EUR и траты 18 EUR увидеть 32 EUR; обновить данные повторно и убедиться, что результат тот же.
3. Подключить, отменить подключение и повторно авторизовать банк; история при истекшем доступе остается видимой, необходимость действия понятна. Настоящие N26/Revolut и особенности Pocket проверяются отдельно.
4. Спросить об оптимизации 30 EUR на пиццу, пояснить «встречаюсь с друзьями»; ассистент предлагает сохранить предпочтение, показывает основания и не меняет план до подтверждения.
5. Проверить учебный долг 1200 EUR при 0%: платеж 200 EUR плюс 100 EUR с 06.10.2026 дает закрытие 06.01.2027; замена дополнительных выплат октября/ноября покупкой 200 EUR дает 06.02.2027. Учебный пример не доказывает доступность покупки и не считается реальным договором.
6. Спросить о покупке AirPods за 200 EUR; проверить извлеченные цену/счет/период, обязательства, резерв, недельный бюджет, влияние на цель и конечную дату проверенного горизонта. Нужный перевод или неизвестный порядок видны как условие.
7. Подтвердить актуальное предложение, повторить нажатие, уйти с экрана и вернуться; изменение применяется один раз, результат можно восстановить. Отказ/закрытие без подтверждения ничего не применяет.
8. Изменить данные или перейти через начало недели перед подтверждением: прежнее предложение не применяется, показан новый расчет и требуется новое подтверждение.
9. Отключить ИИ/не дать согласие/вызвать его недоступность: обзор и обычные расчеты работают; непроверенного финансового ответа нет.
10. Экспортировать, отключить банк, выйти и сменить пользователя, удалить синтетический аккаунт; проверить только собственные данные, прекращение сбора и очистку локальных данных после повторного запуска.
11. После переустановки войти и восстановить серверные данные; другой тестовый владелец их не видит.
12. На настоящем iPhone в личном TestFlight пройти три основных сценария без подсказок; проверить настоящий вход, возврат из банковской формы и уход приложения в фон.

## Edge Cases

| Случай | Ожидаемое наблюдаемое поведение |
| --- | --- |
| Нет операций, но покрытие известно / покрытие неизвестно | Пустой период и неизвестность различаются; обязательства не исчезают |
| Первый импорт, загрузка, один банк недоступен | Понятный статус; последние известные данные и время либо отсутствие данных |
| Нет сети / медленный ответ / ошибка сервера | Кеш с временем доступен для чтения; неподтвержденное изменение не считается выполненным; есть восстановление |
| Нужный источник старше 24 часов либо неполон | Положительный вывод о покупке не выдается |
| Pending становится booked в следующей неделе | Один расход в исходной неделе; исправленная исходная дата пересчитывает период |
| Pending отменен / остаток уже учитывает удержание | Недельный учет исправлен; нет выдуманного банковского остатка или повторного вычитания |
| Собственный перевод, известна только одна сторона | Полный перевод не создает доход/расход; неопределенность и счет оплаты учитываются |
| Возврат 5 EUR к исходным 18 EUR | Остаток исходной недели 37 EUR, текущий лимит автоматически не увеличивается |
| Частичный/превышающий/несвязанный возврат | Бюджетный предел исходного расхода не обрезает реальное зачисление; неясная классификация требует уточнения |
| Неизвестны условия MacBook / неподдержанный профиль | Нужные условия запрошены, дата и доступность не выдуманы |
| Последний платеж / долг не погашается | Переплата не создается, ложной даты закрытия нет |
| Общих денег достаточно, на счете оплаты недостаточно | Видна нехватка на нужном счете или необходимость ручного перевода |
| Дефицит внутри периода, восстановление к концу | Дата и сумма дефицита показаны, итог месяца его не скрывает |
| Только даты / разные as-of счетов / одинаковые моменты / DST | Неизвестный порядок не угадан, зависимый от него результат условный |
| Быстрый повтор / потерянный ответ / перезапуск после применения | Один эффект и восстановленный результат либо безопасное повторное уточнение состояния |
| Истекшая сессия / неизвестный код причины / неверный контракт | Чужие данные и ложный успех не показаны; понятное восстановление |
| В банковском тексте есть инструкции / неправильное действие ИИ | Серверные ограничения соблюдены; новые права и неподтвержденное изменение не появились |
| Большие суммы, длинные названия, пустые и большие списки | Суммы, смысл состояния и действия остаются читаемыми |
| Светлая/темная тема, Dynamic Type, VoiceOver | Статусы понятны без цвета, значения и действия доступны, порядок чтения осмыслен |
| Выход/смена владельца и повторный запуск | Прежний кеш и токены недоступны; случай не маскируется полным тестовым сбросом |
| Удаление / неудачная отмена у провайдера | Собственный доступ закрыт сразу, сбор/ИИ не продолжаются; активные данные очищены в пределах 24 часов |
| Восстановлена старая копия с удаленным аккаунтом | До открытия сервера удаление учтено; старые сессии/предложения/задачи не возвращают аккаунт |

## Critical Paths

| Группа | Путь и итог |
| --- | --- |
| G01 | Вход → свои данные → переустановка/вход; второй владелец не получает чужие данные, выход очищает локальное состояние |
| G02 | Банковская форма → свой счет → импорт; отмена/чужое подключение не подключают счет, reauth объяснен |
| G03 | Обновление → работа после перезапуска → видимый итог; повтор, авария и квота не создают бесконечное обновление |
| G04 | Импорт всех страниц → согласованные данные; потеря страницы/сбой сохраняют прежнюю активную версию |
| G05 | Повтор/pending/booked/перевод/возврат → корректный учет без двойного расхода или дохода |
| G06 | Данные/время/настройки → правильная неделя и денежный прогноз, резерв не используется дважды |
| G07 | Подтвержденный договор/покупка → сравнение по одинаковому горизонту с учетом счета, последовательности и неизвестности |
| G08 | Согласие/вопрос → разрешенное действие → проверенный финансовый ответ или уточнение/безопасный отказ |
| G09 | Предложение → подтверждение → один эффект и квитанция; устаревший результат пересчитан |
| G10 | Экспорт/отключение/удаление → ожидаемый результат → старое восстановление не воскрешает удаленный аккаунт |
| G11 | Три экрана → корректные состояния → восстановление при offline/ошибке/повторном входе |
| G12 | Тестовый выпуск → совместимый сервер и iOS → приемка TestFlight; восстановление среды проверено до личных данных |

## Model Evaluation Acceptance

Используется согласованный D17 набор синтетических вопросов и бюджетов для трех сценариев, предпочтений, неопределенности и атакующих входов. Проверяются допустимые действия, извлеченные аргументы, финансовый результат и смысл уточнений; дословное совпадение текста не требуется.

При изменении инструкций, инструментов или модели набор сравнивается с утвержденным baseline; критерии задаются до первого принятого прогона. Нарушение обязательной границы, пропущенное сервером в проверяемом случае, блокирует выпуск; корректное отклонение намеренно неверного действия — ожидаемый успех проверки. Точные пороги качества, число повторов и стоимость определяются при настройке модели; ограничения выбранного набора остаются явными. Реальные личные диалоги и банковские описания не служат тестовыми данными.
